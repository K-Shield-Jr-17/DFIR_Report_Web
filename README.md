## 📌 프로젝트 소개

격리된 Windows LAB에서 재현한 침해사고를 대상으로, 초기 유입부터 페이로드 실행, 서비스 경로 악용, LSASS 접근, 파일 집결 및 C2 방향 데이터 전송 정황까지 분석한 프로젝트입니다.

Windows 이벤트로그·Sysmon·네트워크·레지스트리·Chrome History·메모리 분석 결과·Process Monitor 증적을 연결하여 공격 흐름을 재구성했습니다. 기술 분석뿐 아니라 사건 상태, 영향 범위, 대응 권고, 탐지 개선, 증거 관리 항목도 함께 정리했습니다.

보고서는 **A4 페이지형 HTML**로 제공하며, 브라우저에서 문서처럼 읽거나 인쇄 기능으로 PDF 저장이 가능합니다.

> 이 저장소는 실습 증거 기반 분석 산출물입니다. 실제 조직의 탐지·격리·복구·승인 기록이 없는 항목은 미확인 또는 제안 상태로 표시합니다. 사건 종료나 전체 시나리오 성공을 전제하지 않습니다.

## 🔎 분석 범위와 주요 결과

| 분석 영역 | 주요 내용 |
|:---|:---|
| 초기 유입·실행 | Chrome 방문·RunMRU·PowerShell 명령과 `a.exe` 실행 연결 |
| 페이로드 | `a.exe`의 후속 실행 파일 생성·실행 및 비표준 경로 활동 |
| 제어 통신 | 의심 프로세스의 C2 주소 연결과 파일·디렉터리 접근 |
| 권한 상승 | `C:\Company\Updater.exe` 배치와 서비스 경로 가로채기를 통한 SYSTEM 실행 |
| 자격증명 접근 | `Updater.exe`의 LSASS 접근 및 메모리 덤프 정황 |
| 파일 집결·전송 | `TempShare` 공유·ZIP 생성, ZIP 읽기와 C2 송신 정황 |
| 대응·탐지 | 사건 상태, 영향 평가, IOC/IOA, ATT&CK 매핑, 개선조치 계획 |
| 증거 관리 | 원문 XML, 증거 이미지, 해시 목록 및 원본 대조 결과 |

분석에서는 **확인 사실 / 정황 / 미확인 사항**을 구분합니다. LSASS 접근을 자격증명 탈취 완료로, ZIP 읽기와 TCP 송신을 파일 전체 전송 완료로 단정하지 않습니다. LAB의 사설망 C2 통신은 인터넷 유출과도 구분합니다.

## 📖 보고서 보기

1. 저장소 전체를 내려받습니다.
2. 최상위 `index.html`을 브라우저에서 엽니다.
3. 목차와 증거 번호를 눌러 본문·원문을 확인합니다.
4. PDF가 필요하면 상단 **인쇄 / PDF 저장**을 선택합니다.

인쇄 시 **A4, 배율 100%**를 기준으로 확인하고, 브라우저의 기본 머리글·바닥글은 끄는 것을 권장합니다. 보고서 자체의 페이지 번호가 포함되어 있습니다.

**HTML만 복사하면 스타일과 증거 링크가 누락될 수 있으므로 `assets/`, `evidence/`를 함께 유지해야 합니다.**

## 🗂️ 저장소 구성

```text
.
├── index.html          # A4 페이지형 통합 보고서
├── README.md           # 프로젝트 안내
├── vercel.json         # 정적 사이트 배포 설정
├── assets/             # 보고서 스타일 및 부가 이미지
└── evidence/           # 보고서가 참조하는 증거·검증 자료
    ├── xml/            # 일반 이벤트 XML
    ├── sysmon_evidence/ # Sysmon XML 및 검증 결과
    ├── network_attachment/
    ├── registry_evidence/
    ├── additional_evidence/
    └── procmon_evidence/
```

이 배포 디렉터리는 보고서와 참조 증거를 위한 구성입니다. 전체 메모리 이미지·원본 EVTX·PCAP·악성 의심 바이너리 전체를 포함하는 원본 증거 저장소는 아닙니다.
